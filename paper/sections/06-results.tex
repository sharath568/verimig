\section{Results}\label{sec:results}

\maybeinput{tables/main_results.tex}

\textit{RQ1: gate pass rates.} Table~\ref{tab:main} reports every configuration. For the strongest model
(\BestModel), agreement with the references is \PlainEquiv\% with the plain prompt, \TrapEquiv\% with the
checklist, and \AgenticEquiv\% with the repair loop; the rule baseline reaches \RulesEquiv\%. Deployment
succeeds in \PlainGOne\% of plain-prompt runs and \AgenticGOne\% of repair-loop runs. The checklist accounts
for most of the gain. For this model it adds \CheckEffect{} points (95\% CI \CheckEffectCI; cases correct
only with the plain prompt versus only with the checklist: \PlainTrapDisc, Holm-adjusted $\PlainTrapP$),
while the repair loop adds \RepairEffect{} points (\RepairEffectCI; $\TrapAgentP$). Because this model was
selected from the results, we also tested every model: the checklist raised agreement for
\CheckPositiveModels{} models, by \CheckEffectMin{} to \CheckEffectMax{} points, and the gain was significant
after Holm correction for \CheckSigModels. The repair loop ran in \RepairShare\% of repair-loop runs.

A larger model does not help without the checklist. With the plain prompt, the 14B model scores higher than
both 32B variants. The 32B models tend to translate line by line and keep ASE semantics wherever the code
still compiles; in a few runs they also placed \texttt{GO} inside a procedure body, which ends the
procedure early (\GoSplitShare\% of plain-prompt deployment failures). The prompt asks for \texttt{GO}
between batches, which may encourage this. With the checklist, the 14B and both 32B models score within one point of each other; the 32B models
score highest only with the repair loop, and the 4-bit and 8-bit variants differ by less than their
intervals, so the data do not distinguish them.

\textit{RQ2: failures that pass compilation.} For the strongest model, \PlainSilentGivenCompile\% of the
plain-prompt translations that deployed disagreed with the reference. Overall, \PlainSilent\% of its
plain-prompt runs and \AgenticSilent\% of its repair-loop runs passed G1 and G2 but failed G3. A pipeline
that checks only compilation and lint would accept these translations. With the repair loop,
\BestAgentSilentShare\% of the model's remaining failures are of this kind.

\maybeinput{tables/observability.tex}

\textit{RQ3: where the failures come from.} Table~\ref{tab:observability} splits agreement by category
type. With the checklist, which names the silent categories, the strongest model reaches
\AgenticSilentClassEquiv\% on cases labelled silent (plain prompt: \PlainSilentClassEquiv\%) but
\AgenticCompileClassEquiv\% on cases labelled compile (plain prompt: \PlainCompileClassEquiv\%). The
remaining errors come from translating constructs that SQL Server rejects as written. The model replaces
them with code that compiles but behaves differently: the GROUP BY extension becomes grouping or
partitioning by row (C10, C28), a right outer join keeps the wrong table (C29), unsigned types become signed
types of the same width and overflow on large values (C35, C36), and the transaction-mode check becomes
\texttt{@@TRANCOUNT = 0}, which differs only under implicit transactions (C18). For this model, all of these
errors (\BestSilentFirstAttempt\%) were already present in the first translation and were not introduced by
the repair loop. Across all models, the loop ran in \RepairRuns{} runs; \RepairToPass{} of them ended in
agreement, \RepairToSilent{} ended in a translation that passed G1 and G2 but failed G3, and
\RepairStillLoud{} still failed G1 or G2.

\maybeinput{tables/failures.tex}

\textit{Error analysis.} Table~\ref{tab:failures} lists the cases that most often passed G1 and G2 but
failed G3. Two further patterns appear across models. A rewrite can avoid a lint rule while keeping the
error: one model translated \texttt{mgr\_id = null} as \texttt{mgr\_id = convert(int, null)}, which the
lint does not match and which still returns no rows (C08). Error handling is also fragile:
\texttt{raiserror (20001, 16, 1, ...)} raises SQL Server's built-in replication message 20001 instead of
the intended text, and \texttt{THROW} rejects ASE's user-error numbers (C05).

\textit{Test adequacy and interfaces.} The original inputs detected \MutKilledInitial{} of
\MutTotalInitial{} mutants. We inspected every survivor. Some were equivalent mutants that no input can
reveal, some changed a return code after a raised error, which G3 does not capture because the driver
reports the error and drops the later result, and the rest showed missing boundary inputs: no order or sum
exactly at a threshold, no transfer of the full balance, and only Latin characters in Unicode columns. We
added inputs for those cases and re-scored all stored translations with them. The final inputs detect
\MutKilled{} of \MutTotal{} mutants, or \MutScoreNonEquiv\% of the \MutNonEquiv{} that are not
equivalent (Table~\ref{tab:mutants}).

\textit{Held-out procedures.} On the \NumHeldout{} held-out procedures (\HeldoutRuns{} graded runs), the
strongest model reaches \HeldoutPlainEquiv\% with the plain prompt (95\% CI \HeldoutPlainCI),
\HeldoutTrapEquiv\% with the checklist (\HeldoutTrapCI), and \HeldoutAgenticEquiv\% with the repair loop
(\HeldoutAgenticCI); the rule baseline reaches \HeldoutRulesEquiv\%. The checklist also helps on code it was
not written from, but with six procedures the intervals are wide, and these results are preliminary. The two
procedures the strongest model never translated correctly failed on details. In the regional report, every
run translated both outer joins and all NULL tests correctly but raised the wrong error: one used
\texttt{RAISERROR(20010, ...)}, which SQL Server maps to a built-in replication message, and two kept the
\texttt{!} of ASE's \texttt{\%1!} placeholder in the message. In the department view, every run placed
\texttt{GO} inside the procedure, so its second query was lost, and one run also grouped by row. The repair
loop mattered only for the weakest model: \WeakModel{} needed \WeakAttempts{} attempts per procedure on
average, which raised deployment from \WeakTrapGOne\% to \WeakAgenticGOne\% and agreement from
\WeakTrapEquiv\% to \WeakAgenticEquiv\%. The strongest model's translations never needed repair
(\HeldoutRepairShare\%).

\textit{RQ4: size, quantization, and latency.} Fig.~\ref{fig:scaling} plots agreement against mean model
latency per case. With the repair loop, the 14B model is slightly less accurate than the 32B models at lower latency, and
DeepSeek-Coder-V2 Lite scores lowest under every converter. Every configuration translates a case in
seconds on one workstation.

\textit{RQ5: reconciliation.} Table~\ref{tab:reconcile} gives detection rates per fault type. Over the
standard faults, row counts detect \RecRowcount\% (\RecRowcountN; 95\% CI \RecRowcountCI), the aggregate
checksum \RecAggregate\% (\RecAggregateCI), the naive row hash \RecRowhashNaive\% (\RecRowhashNaiveCI), and
the unambiguous row hash \RecRowhash\% (\RecRowhashCI), with \RecFalsePos{} false positives on clean trials.
Row counts only see faults that change the number of rows, so truncation, character-set loss, rounding, and
precision loss all pass a count-only check. The aggregate checksum misses values swapped between two rows,
which is consistent with an order-insensitive combination of row checksums. On the adversarial faults the
naive hash detects \RecRowhashNaiveAdv\% and the unambiguous hash \RecRowhashAdv\%: the naive encoding
missed every trial in which a NULL became the text \texttt{<NULL>}, a value moved across the separator, or a
value changed after its first 4{,}000 characters, and found only the duplicated key. The unambiguous hash
took a median of \RecMsRowhash{}~ms for the 2{,}000-row table on both sides, against \RecMsNaive{}~ms for the
naive hash. These rates hold for the
tested faults only; each fault type is weighted equally, so they are not estimates of detection rates in a
real migration.
